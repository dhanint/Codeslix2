Ringkas: Aplikasi ini adalah konsol untuk membaca, menulis, dan mengelola tag RFID ICODE SLIX2 (standar ISO 15693 / NFC-V) langsung dari ponsel Android — termasuk peta memori, informasi sistem, EAS, proteksi password, privacy mode, hingga originality signature.

1Pengenalan

ICODE SLIX2 (NXP SL2S2602) adalah IC label RFID pasif 13,56 MHz yang patuh ISO/IEC 15693 dan dikenali Android sebagai teknologi NfcV. Chip ini menyimpan data dalam blok 4-byte dan punya fitur keamanan: AFI/DSFID, EAS, proteksi halaman berbasis password, privacy mode, destroy, serta originality signature.

SLIX2 Console membungkus seluruh perintah tersebut dalam satu layar ber-tab yang rapi, lengkap dengan konsol frame mentah (hex) untuk keperluan lanjutan dan mesin token V1.4/V1.8.

2Tampilan Antarmuka Baru

GUI dirancang ulang bergaya kartu modern: header gradien biru-navy, tab berbentuk pill, panel kartu membulat, konsol bergaya terminal gelap, peta memori zebra, dan status-bar kontras.

3Memulai — Menyiapkan HP & Tag

  1. Aktifkan NFC di ponsel: Settings → Connected devices → NFC. Aplikasi butuh izin android.permission.NFC (sudah tertanam).
  2. Buka SLIX2 Console. Layar dikunci mode potret. Status-bar menampilkan "Tempelkan tag SLIX/SLIX2…".
  3. Tempelkan tag ICODE SLIX2 ke bagian antena NFC HP (biasanya sepertiga atas bodi belakang). Begitu terbaca, UID muncul di chip header dan konsol mencatat "# Tag terdeteksi. UID = …".
  4. Tekan Read Tag untuk dump seluruh blok ke peta memori, atau Activate untuk sekadar menampilkan UID.
Addressed vs Non-addressed. Centang Addressed bila ada lebih dari satu tag di medan, atau perintah mewajibkannya (mis. Write/Set/Lock password, Destroy). Saat Addressed aktif, UID disertakan pada frame dan flags berubah dari 0x02 → 0x22. Bila tag menolak, coba aktifkan UID balik (urutan byte UID dibalik).
Format tampilan. HEX menampilkan byte apa adanya (default), ASCII mengubah byte cetak menjadi karakter, DEC menampilkan nilai desimal 0–255. Pilihan ini hanya memengaruhi tampilan peta memori — bukan data di tag.

Membaca satu blok langsung

Di tiap baris peta memori: R membaca ulang blok itu, W menulis 4 byte (dialog hex), L mengunci blok (permanen, minta konfirmasi).

4Panduan Operasi per Tab

Tab 1 — Commands

  • Konsol + frame bebas: ketik hex mis. 02 20 48 lalu Send untuk mengirim frame mentah; Clear mengosongkan log.
  • Tombol cepat: Read Tag, Sys Info, NXP Sys, Signature, Random.
  • Token V1.4 / V1.8: pilih firmware, isi MASTER_KEY (32 byte hex), kode produk, counter; untuk V1.8 isi data transmisi blok 32–51 (80 byte). Tekan Hitung Token — jika memori sudah di-dump, token otomatis diverifikasi terhadap isi tag.

Tab 2 — System

  • Get System Info mengisi otomatis: MANF, Type, AFI, DSFID, jumlah BLOCKS, ukuran blok, IC REF.
  • AFI / DSFID: tombol SET menulis nilai 1-byte, LOCK menguncinya permanen.
  • Tx/Rx: info laju modulasi (ASK100/ASK10, 26/53 kbps).

Tab 3 — Operations

  • Get Multiple Block Security Status — status kunci seluruh blok.
  • Stay Quiet / Reset to Ready / Select — kendali state ISO 15693.
  • Multi Block Write — tulis rentang blok From→To sekaligus.
  • Request Flag builder — centang bit 0–7, nilai flag tampil langsung (mis. 0x02).

Tab 4 — ICODE SLIX

  • EAS: Set/Reset/Alarm/Lock.
  • Inventory Read: isi AFI, First, MaskLen, Num, Mask value, opsi Fast → SEND.
  • Random Number dan EAS/AFI Password (Write/Set/Protect EAS/Protect AFI).

Tab 5 — ICODE SLIX2

  • Originality Signature — baca tanda tangan 32-byte (keaslian NXP).
  • Passwords: Read, Write, Privacy, Destroy, EAS/AFI. Tekan GET (RND) lalu kolom XOR terisi otomatis. Tiap baris punya SET (kirim via XOR), WRITE (ganti clear), LOCK.
  • Page Protection — Start Page H, centang Read/Write proteksi Page L/H, Write & Lock Protection.
  • Aksi: Enable Privacy, Stay Quiet Persistant, 64 Bit Protection, Destroy.

Tab 6 — NXP System

Tekan GET untuk membaca PP pointer, PP Conditions, Lock Bits, dan Feature Bits (counter, EAS-ID, privacy, destroy, signature, dll.) dalam tabel Yes/No.

5Alur Password & Perintah Aman (XOR)

Perintah sensitif (Set Password, Enable Privacy, Destroy, 64-bit Protect) tidak pernah mengirim password mentah. Alurnya memakai angka acak sekali-pakai dari tag:

Rumus XOR (lihat IsoConsole.xorPw):
mask = {RND[0], RND[1], RND[0], RND[1]}
XORpw[i] = PW[i] ⊕ mask[i], i = 0..3
Destroy & Lock bersifat PERMANEN. Destroy mematikan tag selamanya; Lock tak bisa dibuka. Aplikasi meminta konfirmasi, tetapi tidak ada cara memulihkan tag setelahnya.

Beda SET vs WRITE password

AksiPerintahIsiTujuan
SET0xB3id + XORpw(4)Autentikasi untuk membuka area terproteksi pada sesi ini
WRITE0xB4id + pw(4)Mengganti nilai password tersimpan (clear, perlu Addressed)
LOCK0xB5idMengunci password agar tak bisa diubah lagi

Identifier password: Read=0x01, Write=0x02, Privacy=0x04, Destroy=0x08, EAS/AFI=0x10.

6Arsitektur Transmisi — Lengkap

6.1 Lapisan (dari aplikasi ke udara)

Aplikasi menyusun intent perintah; IsoConsole membangun byte frame dan menerapkan aturan flags/UID/XOR; Android NfcV.transceive() menambahkan CRC-16 & framing lalu mengirim lewat NFC controller; tag menjawab pada kanal 13,56 MHz secara half-duplex.

6.2 Struktur Frame Perintah

Dibangun di IsoConsole.send(): head = nxp ? [flags, cmd, 0x04] : [flags, cmd]; bila Addressed → sisipkan UID (LSB-first) sebelum parameter. CRC ditangani lapisan NfcV.

6.3 Byte Flags Permintaan

BitFungsiCatatan
bit 0Sub-carrier0 = single (default)
bit 1Data rate1 = high (26 kbps) — dipakai app
bit 2Inventory1 = frame inventory
bit 3Protocol ext.0 normal
bit 4Select1 = hanya tag ter-select
bit 5Address1 = Addressed (sertakan UID)
bit 6Optiondipakai Write/Protect tertentu
bit 7RFUcadangan

Non-addressed = 0x02 · Addressed = 0x22 · Option aktif → OR 0x40. Inventory memakai 0x06 (+0x10 bila AFI).

6.4 Pola Respons

Byte-0 respons = Response Flags.

  • 0x00 → sukses; byte berikutnya = payload.
  • bit0 = 1 → error; byte-1 = kode error.

<< 02 2B
>> 00 0F 27 2D D6 … (OK)
>> 01 0F (error 0x0F)

Helper: ok() cek flags==0x00; payload() buang byte flags.

8Catatan Keamanan & Praktik Baik

Operasi ireversibel: Destroy (0xB9), Lock Block/AFI/DSFID/Password, dan Lock Page Protection tidak dapat dibatalkan. Uji pada tag korban dulu.
  • Selalu Get Random Number tepat sebelum perintah ber-XOR agar nilai acak masih valid (anti-replay). Jangan pakai ulang RND lama.
  • Perintah penulisan/penguncian password umumnya butuh Addressed — aktifkan centangnya.
  • Simpan MASTER_KEY token di tempat aman; jangan tanam di repo publik.
  • Gunakan konsol frame bebas hanya bila paham byte yang dikirim — frame salah bisa mengubah konfigurasi tag.
  • Verifikasi keaslian lewat Read Signature (0xBD) sebelum mempercayai sebuah tag.

Ringkasan alur kerja yang disarankan

  1. Tempel tag → Read Tag (dump) → periksa System & NXP System.
  2. Baca Signature untuk cek keaslian.
  3. Jika perlu proteksi: SET Read/Write pw → Protect Page → (opsional) Lock.
  4. Untuk pensiun massal aset: EAS / Privacy; untuk pemusnahan: Destroy (hati-hati).
